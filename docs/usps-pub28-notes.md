# USPS Pub 28 notes

The source of every rule the parser and the emitters apply: a Pub 28 section, or, where Pub 28 is silent, the data or decision behind it. A rule change adds or edits its row here (`CONTRIBUTING.md`). Publication: [USPS Publication 28](https://pe.usps.com/text/pub28/welcome.htm), the current online edition (October 2026).

**Notation.** `§N` is Pub 28 section N. `#N` is an issue of this repository; it holds the counts and the discussion behind a rule. "Corpus `xx-001` to `xx-009`" are the rule's golden-corpus cases. "Observed" means seen in address data, with no USPS text. Examples are invented. Which release changed a key: [`CHANGELOG.md`](../CHANGELOG.md).

## Lexicon tables

`crates/doorplate/data/*.toml` is compiled into static tables by `build.rs` and read only through `Lexicons`. `build.rs` rejects a spelling that maps to two entries, a duplicate abbreviation or code, a form that is not a normalized key, and an entry whose `forms` leave out its own name or abbreviation.

**Verified** in October 2026: each table was transcribed from open-source copies (usaddress-scourgify and the street-address gem, both MIT) and compared with the live Pub 28 pages, with no differences. Rerun: `python3 tools/pub28/verify.py --cache DIR --fetch --emitter`; it also runs every Appendix F example through the parser and the USPS emitter (all match except `SR MM`, which is left to state data on purpose).

Pages are under `https://pe.usps.com/text/pub28/` (`pe.usps.com` refuses clients without a browser User-Agent). Chapter 2: 211 `28c2_001`, 212 `_002`, 213 `_003`, 215 `_005`, 221 `_006`, 222 `_007`, 223 `_008`, 224 `_009`, 225 `_010`, 231 `_012`, 232 `_013`, 233 `_014`, 237 `_018`, 238 `_019`, 239 `_020`, 241 to 246 `_021` to `_026`, 251 to 255 `_027` to `_031`, 261 and 262 `_032` and `_033`, 281 to 285 `_036` to `_040`. Chapter 3: 341 `28c3_012`, 343 `_014`, 35 `_015`, 354 `_019`, 356 `_021`. Appendices: A1 `28apa_002`, B `28apb`, C1 `pub28apc_002`, C2 `pub28apc_003`, D1 `28apd_002`, D4 `28apd_005`, F `28apf` (all `.htm`). The examples in 215, 238 and 239 are images and were not re-read.

### Non-Pub 28 spellings

A spelling Pub 28 does not list goes in an `observed = [...]` list with a source comment. A lookup returns it as `MatchKind::Observed` and the parser raises `non_standard_abbreviation`. Source for all: Florida county address data.

| Spelling | Resolves to | Table |
|---|---|---|
| `TRC` | TRCE (TRACE) | suffixes |
| `LP` | LOOP | suffixes |
| `UN` | UNIT | units |
| `LT` | LOT | units |
| `BLV`, `BL` | BLVD (BOULEVARD) | suffixes |
| `TE` (grid streets such as `NW 127 TE`) | TER (TERRACE) | suffixes |
| `APTO`, `AP`, `APART`, `APARTAMENTO`, `APPT`, `APARTAMENT`, `APP`, `APRT` | APT (APARTMENT) | units |
| `SUIT` | STE (SUITE) | units |

- `AP` is also the Armed Forces Pacific code. The tagger reads the last line first, so `APO AP 96xxx` keeps it as the state.
- Also `observed`, from the older transcriptions and not from field data: 20 suffix spellings C1 does not list (`CRT` for COURT, `CK` for CREEK, `LA` for LANE, `TR` for TRAIL) and HANGAR. The per-entry comments in `suffixes.toml` and `units.toml` list them.
- State `aliases` (`FLA`, `CALIF`) are pre-ZIP abbreviations, not Pub 28 forms: accepted as input (`MatchKind::Variant`), never emitted.

### Lookup rules

- Keys are normalized by `lexicon::normalize_key`: uppercase, periods removed, whitespace collapsed, trimmed (`P.O. Box` looks up as `PO BOX`). Data files must already be in that form (`build.rs` checks).
- A spelling can belong to several tables (FL is a state and FLOOR; KEY is a suffix and a designator; CR is circle and county road; ST is street and saint; RD is a suffix, a route form and a highway prefix; ROUTE is a route form and a highway prefix). The lexicon answers each table alone; choosing by position is the tagger's job.
- State-dependent spellings (SR is State Road in Florida and State Route elsewhere; RR is Ranch Road in Texas) stay out of the base tables and come from state data. A state's `overrides.toml` can also read a base spelling differently; the base tables read `CR` as CIRCLE (observed), not CREEK, because the evidence says so.

## Parser rules

How the tagger (`crates/doorplate/src/tagger/`) reads an address, grouped by the part of the address a rule touches. Where Pub 28 is silent the source is the data or a decision, said so in the Source column. The last-line rules (ZIP, state, city), the rules for input on one line and those for the second address line have sections of their own; "Left as it is on purpose" lists the readings decided against.

### Street line

| Rule | Source |
|---|---|
| Read the last line first, then the delivery line from both ends: units and postdirectional from the right, house number and predirectional from the left. | §231 (parse from the right-most element). |
| One or two directional words before the name are the predirectional, after the name and suffix the postdirectional, in the Appendix B forms. A directional with no name beside it is the name (`2 SOUTH ST`). `N W`, `N E`, `S W`, `S E` written as two letters are listed spellings in `directionals.toml`. | §233.1, 233.21, 233.22; Appendix B; spaced forms seen in Florida address data. |
| A one-letter directional right after a lone suffix word is part of the name, like any letter there (`AVENUE G`). | §233.3 (alphabet indicators); Florida address data. |
| The suffix is the last word before units and postdirectional, when a name is left before it; earlier suffix words stay in the name (`EAGLES POINT CIRCLE`). | §234; Appendix C1. |
| Two suffix words in a row: the second is the suffix, the first is part of the name, written in full (`HARBOR VW DR` is `HARBOR VIEW DR`). Only a standard abbreviation is spelled out; after a number `ST` and `RD` are the ordinal's ending (`21 ST AVE`). Corpus `p28-twosuf-001` to `006`. | §234.2; Appendix F (`HIGHWAY 3 BYP ROAD`). |
| A highway is a `[[highway]]` prefix after the house number (or predirectional) and a route that starts with a digit; prefix and route go in `highway`, later words are suffix, postdirectional or name (`US 41 SW`). `I10` and `IH280` are split by the tokenizer. | §237; Appendix F. |
| A state code or name before a highway prefix goes in `highway.state` (`CA COUNTY RD 150`); before an all-digit route it gets the HIGHWAY prefix (`KY 1207`). Tried after the plain and predirectional forms, so `NE HWY 5` keeps NE; the bare form skips states that are also directionals (`NE 5TH ST`). A state that is also a designator counts (`5100 FL 40 SUITE 100`). A state that is the whole name (`OKLAHOMA AVE`) is the name. | Appendix F and its note. |
| A route keeps up to two letters run into its number (`ROUTE 1150EE`); a longer word run into a house number is still split (`101BRADDOCK`). Corpus `p28-highway-038` to `040`. | Appendix F (`ROUTE 1150EE`, `COUNTY HIGHWAY 60E`). |
| After a highway prefix a route may start with a letter: one letter, digits, at most one more letter (`HIGHWAY A1A`). Corpus `rg-121`. | Appendix F; Florida address data. |
| After COUNTY ROAD or COUNTY HIGHWAY a route may be one or two letters (`COUNTY ROAD J`). | Appendix F (letter routes). |
| Hyphenated routes split: `GA-25`, `US-385`, `I-65`, when the letters are a highway prefix or a state code that is not a directional. `SR-54` and `NE-2` stay whole. | Appendix F; library choice. |
| Name words after a route belong to the street only on the route's line or segment, and the emitters keep them (`HIGHWAY 66 FRONTAGE RD`); on a later line they are unparsed. | Appendix F; bug fix. |
| `COUNTRY ROAD` or `COUNTRY RD` before a route number is an observed typo for COUNTY ROAD; without a number it stays a name. `HGWY` is an observed spelling of HIGHWAY. | usaddress test data; Florida address data. |
| `CR` after a street name is `CIRCLE`; `CTY RD`, `CTY ROAD` and `CTY HWY` before a route number are `COUNTY ROAD` and `COUNTY HIGHWAY`, in every state: `12 BAYVIEW CR` is `BAYVIEW CIR`. All three are observed spellings. `CR 12` stays `COUNTY ROAD 12`. Corpus `cy-001` to `cy-009`. | Appendix C1 lists `CIR` forms and `CRK`, not `CR`; Appendix F has `CO` and `CNTY`, not `CTY`; address data in four all-state sources. |
| State data may add a highway prefix read in that state only: `SR` is STATE ROAD in Florida (`22200 SR 60`), a street name elsewhere. It applies to pre-split fields from the state field, a ZIP alone or `default_state`. Corpus `ff-001` to `ff-005`. | Appendix F maps `SR` to both STATE ROAD and STATE ROUTE, so it is state-dependent; Florida address data; `docs/states/fl.md`. |
| `DRT` is `DR`, `LNE` is `LANE`, `SU` is `SUITE` (observed spellings). | Not in C1 or C2; Florida address data. |
| A road number written before the road type is a street name with the number first: `331 5659 PRIVATE ROAD` is `5659 PRIVATE RD`, from a three- or four-digit number and `PRIVATE`, `COUNTY`, `STATE`, `FM` or `FARM TO MARKET`. Corpus `np-013`, `np-019` to `np-025`. | Data: the number identifies the road (#542, #316). |
| A road number after `<WORD> ROAD` stays in the street for a closed list of state and word pairs (`PRIVATE ROAD 1234` in TX); any other `<word> RD n` keeps the number as a unit. Corpus `rn-001` to `rn-007`. | Data: National Address Database street names (#593). |
| A bare number after a county road and a compass pair is a unit: `CR NE 12` reads the number as the unit. Only `NE`, `NW`, `SE`, `SW`; a single letter is a route letter. Corpus `cd-001`, `cd-002`. | Data: National Address Database count and reviewer cards (#642). |
| A single letter after `ROAD`/`RD` on one line with no commas stays with the street as a unit (`# B`) when city words follow it; not a directional letter, not `O`, `D`, `L`, not before a unit word, not when the place list knows the city. Corpus `rl-001` to `rl-005`. | Pub 28 writes a bare letter after the street as `# B`; probe `road-letter` (#600). |
| A spelled-out compass word before a suffix with nothing else in the street is the name, and a value with a digit after it is a unit: `44 WEST AVE 2B` is street `WEST AVE`, unit `2B`. Only `NORTH`, `SOUTH`, `EAST`, `WEST`; a letter alone stays a lettered avenue. Corpus `cn-001` to `cn-010`. | §233 (nothing is left to be the name if the compass word is the prefix); Boston review. |
| `KY` and `TR` after a spelled-out compass word and before a number are the road's name: `88 NORTH KY 8` is `N` and `KY 8`; `1234 EAST TR 56` is `E` and `TR 56`. Corpus `cn-011` to `cn-015`. | §233; C1 lists `KY` as `KEY` and `TR` as `TRL`, but a number straight after means a numbered road; NAD labels and a precision queue. |
| `NO` right after the house number, before a plain word or an ordinal, is north: `464 NO MAPLE AVE` is `N MAPLE AVE`. A phrase list keeps `NO` in the name (`NO MANS LAND`), and so do a bare number, suffix, highway, unit or direction word after it. Corpus `nn-001` to `nn-011`. | Data: the word after `NO` decides (#470); Pub 28 lists `N` and `NORTH`. |
| `SO` as the last word of the street, after a suffix or grid number, is the postdirectional south: `84 ELMHURST PL SO` is `ELMHURST PL S`. `SO` first or in the middle of a name, or before a name word, is unchanged. Corpus `so-001` to `so-007`. | Data: `so-for-south` probe (#269); Appendix B has `S` and `SOUTH` only. |
| A direction after a lone `BOULEVARD` or `PARKWAY`, spelled out or a letter, is the postdirectional (`BOULEVARD EAST`); after any other lone suffix a letter stays in the name (`AVENUE N`). Corpus `bd-001` to `bd-005`. | §233 (direction after the name); NAD street names (#549). |
| A lone directional right after the suffix, an ordinal or a grid number is the postdirectional, not a copy of the city's first word: `123 MAIN ST WEST` with city `WEST POINT` keeps `W`. A cut-off copy of a non-directional city word is still dropped. Corpus `rg-207` to `rg-211`. | §233; scoring against NAD labeled parts. |
| A postdirectional is not a cut-off copy of the city: `1040 HANCOCK CHAPEL RD NE, NEW SALISBURY, IN` keeps NE. Corpus `nat-015`, `nat-016`. | Library choice. |
| A postdirectional alone after a comma belongs to the street (`2272 GOODWOOD BLVD., SE`). A comma after a lone directional that follows the house number is dropped when the next segment ends in a suffix (`3324 N, ANDREWS AVE`). Corpus `rg-192` to `rg-194`. | §233; §222 (punctuation may be omitted); Florida address data. |
| A directional letter right after the suffix, then a number, is the postdirectional and a bare unit (`DR E 203`). Corpus `rg-127`, `rg-128`. | §233; Florida address data. |
| A directional after a designator is that designator's value only when the designator always takes one (APT, STE, UNIT: `APT N`); after any other designator it is the postdirectional and the word stays in the name (`123 OCEAN FRONT W`). Corpus `rg-189` to `rg-191`. | §213 lists which designators need a value; national address database. |
| A number of one to three digits run into `ST` or `RD` that is not its ordinal ending is the number and the suffix (`178ST` is `178 ST`; `21ST` stays). Corpus `rg-124` to `rg-126`. | Florida address data. |
| A period after an abbreviation of two letters or more, with a letter after it, separates words (`ST.CLOUD`), unless the pieces join into a known word (`BLV.D`); initials stay joined (`P.O.`). A box word joined to its number by punctuation is split (`BOX.2351`). Corpus `rg-133`, `rg-135`, `rg-136`. | §354 (Pub 28 drops periods); Florida address data. |
| A stray backtick is trimmed (`1719\``). | §354 (punctuation removal). |
| A word before a trailing `CT`, `KY`, `MT`, `WY` or `LA` is not cut in two: the glued-city rule reads such a code as a state only when a ZIP of that state follows (`9 ELM WALLINGFORD CT 06492`); `1305 PINEBRIAR CT` keeps its name. Corpus `gl-001` to `gl-011`. | Data: auction listings and the seven large sources. |
| A street suffix glued to a city (`STREETDADE CITY FL`) is split only when the city is anchored: by a state or ZIP that ends the segment, or by a next segment starting with a state or ZIP; a word that completes a place (`PICO RIVERA`) is never split. Corpus `nat-001` to `nat-008`. | Found by comparing with a national address database. |
| Intersections: `&`, `@`, `AND` or `AT` between two streets in one segment split the input: the first street is parsed, the rest is `unparsed`, `intersection_detected` is raised and `key()` and `slug()` are `None`. `LAND AND SEA RD` and `AT&T WAY` are single streets. Corpus `is-001` to `is-013`. | Pub 28 does not address intersections. |
| A highway modifier before a city on one line, and a PO Box on line 2 beside a street with no number, are left as they were. | Standing decision: no volume in the data. |

### House number

| Rule | Source |
|---|---|
| County grid numbers are house numbers: digits and one or two compass letters, each followed by digits (`22W410`, `W338S9739`). A grid number written in two parts is one number (`N165 W2123`). A lone compass letter and a number of three digits or more, with a street word after, is one grid number (`N 10129 MAPLE RD` is `N10129`; `E7608B` takes one letter). | Appendix D2 (grid addresses; it names the Salt Lake City form, not these); observed in address data. Corpus `rg-195` to `rg-201`. |
| A letter followed by two digits or more at the start of the street is a house number (`T703 STATE ROUTE 66`); a letter alone is not. | Library choice. |
| Two plain house numbers of three or more digits (`1309 1329 E VINE ST`): the first is the address's, the rest are left unparsed with `multiple_addresses`, only when a whole street follows. Rural grid streets (`1575 NORTH AVE`) and a split ordinal (`139 TH AVE`) keep the number in the name. | Observed in Florida address data; Appendix D2 (grid names). |
| House number `N-N` is one hyphenated number (`112-10`), unless the second part has as many digits and is larger (`1204-1206`): that raises `multiple_addresses`, except in Queens, NY (next row). | Appendix D1; §232. |
| One trailing letter belongs to a hyphenated number: `12-34A` is one number, as `12-34` and `1234A` are. `12-34AB` and `12-34-5A` are not; `1204-1206A` is one number. Corpus `hn-001` to `hn-009`. | Appendix D1, §232; New York corporation records (mostly Queens ZIPs). |
| A letter before the hyphen is part of the number: `53A-53 HOLLIS AVE` is one number kept as written; the range test is the one for `12-34` (`53A-54` raises `multiple_addresses`). One letter only; `53AB-53` and `53 A-53` are not a number. | §232 gives `112-10`, no lettered form; the Massachusetts convention, Boston review (#225). |
| In Queens, NY the part before the hyphen is the cross street, so a hyphenated number with a larger second part is one address: `multiple_addresses` is not raised when the resolved place has county `QUEENS` and the range was the only cause. Manhattan (`20-22 W 45TH ST`) still warns. Not applied when no place resolves. | Secondary sources only, no official one found: StreetEasy and Steve Morse's Queens format page; county from the place list (`docs/places.md`). |
| In Queens the key drops the hyphen of a number of one to three digits, a hyphen, two digits and an optional letter: `37-12 82ND ST` and `3712 82ND ST` share a key. Elsewhere the hyphen stays; `street_number` and the slug keep what was written. Corpus `qk-001` to `qk-009`. | Same sources as the row above; New York records show the hyphenated and plain forms for the same address (#312). |
| A hyphen with a space on both sides between the house number and a second number is a separator: `1900 - 938 PAVILION DR` reads as `1900 938 PAVILION DR`; the second-number rules decide. Only with a US state other than NY, MA and HI; one-sided hyphens are a unit already. Corpus `hp-001` to `hp-006`. | Pub 28 has no second number before the street; `hyphen-before-second-number` queue (#612). |
| A second number between the house number and a street is read by state. In a New York City ZIP, in Massachusetts (one to three digits and two) and in Hawaii (two and three or four) it is the house number as written, the key writing a hyphen (`41 12 80TH AVE`). Elsewhere it is a unit: `31 208 BIRCH LN` is number 31, unit 208; before an ordinal street a different number of up to four digits is the unit (`123 104 11TH ST`); a repeated number is dropped with `repeated_text`. A second number 1 to 20 above the first with the same parity (`7310 7312 OAK DR`) is a range and warns. A one or two digit number may start a numbered street (`12 4 ELM ST`). Corpus `np-001` to `np-017`, `np-026` to `np-031`. | Data: 90 reviewed probe cards for #313, #501, #502 and the #544 queues; #590 and #591. |
| A unit designator right after the house number, with a bare unit value on line 2, is that unit's type: `123 APT OAK LN` / `1 100` is street `OAK`, unit `APT 1 100`. Only `APT`, `APARTMENT`, `STE`, `SUITE`, `UNIT`, `RM`, `ROOM`; a line 2 with its own designator is unchanged. Corpus `sdb-001` to `sdb-005`. | §213 puts the designator after the street; probe `stray-designator-before-name-b` (#498). |
| A unit between the house number and the street is a unit: `123 SUITE A OAK ST` is number 123, unit `STE A`. Only `APT`, `BLDG`, `RM`, `STE`, `UNIT`, with a value that is not an ordinal and a street left over; the street may have no suffix (`242 APT B EXAMPLE`); a line 2 of `#` and the same value is a copy. Corpus `ubs-001` to `ubs-015`. | Not USPS (§213 puts the unit after the street); every large source (#296, #529). |
| A single letter after a plain house number that went into a street name of more than one word raises `ambiguous_number_letter` (`123 A MAIN ST`); not when the letter is stuck to the number, is a directional, is the whole name (`123 A ST`) or is the `U` of `U S ROUTE`. | Pub 28 does not address it; NAD sample (`docs/warnings.md`). Corpus `nat-013`. |
| A letter `A` to `D` stuck to the house number (`123B ELM ST`) stays the number's suffix and raises `glued_number_letter` (warning only). Not for `E` to `Z`, a hyphenated letter or a box number. Corpus `gnl-001` to `gnl-006`. | Not USPS; owner decision (#653, option 3) after counts over six sources. |
| A letter `A` to `D` after a plain house number and before a name word is a unit: `46 A LINDEN AVE` is number 46, street `LINDEN AVE`, unit `A`, still with `ambiguous_number_letter`. Not before a single letter, a suffix (`123 A ST`), AND, a unit or box word, or a non-word, nor after a grid number; `E` to `Z` keep the street name; a unit written with a designator keeps the first slot. Corpus `nlt-001` to `nlt-014`, `rg-070`, `wn-001` to `wn-006`. | Not USPS; owner decision from the reviewers (#360: 88% of `A` to `D` cards a unit; #270, #297, #466, #487). |
| A single letter between the house number and a directional belongs to the number (`428 B SOUTH MAIN ST`) for `E` to `Z`; for `A` to `D` it is the unit (row above). | Library choice, narrowed after real data. |
| A half or quarter written without its slash is a fraction: `31 1 2 ELM PLACE` is `31 1/2`; `838 21 1 2 RD` is number 838 and street `21 1/2 RD`. Done in the tokenizer when the next token is a plain word; a unit or box word next, a bare suffix, a third number, or a lone non-direction letter keep the digits apart. Corpus `rg-154` to `rg-161` for the line-2 form. | Appendix D4 gives `123 1/2 MAIN ST` with the slash; carrier census review (#387). |
| A hyphen before a fraction is a space (`1174-1/2` is `1174 1/2`). | §232; national address database. |
| Spelled-out numbers: `ONE` to `TWENTY` opening the street line is the house number when a name and a suffix follow and the first name word is not a unit, highway, suffix or digit word (`ONE NORTH MAIN ST` is `1 N MAIN ST`); not a numbered street (`ONE MILE RD`, `[numbered_street]` in `special.toml`). A number word after a value-taking designator is the unit number (`SUITE TWO` is `STE 2`). A spelled ordinal before a floor word is the floor (`THIRD FLOOR`). Corpus `sp-001` to `sp-016`. | Pub 28 does not say (§235 on numeric street names; §212 and §232 do not mention spelled numbers); the data and the IRS reviewer. |
| The first name word may also be a singular suffix word (`ONE PARK AVE`, `TWO WALL ST`), and an ordinal or compass word after a direction (`TWO WEST 47TH ST` is `2 W 47TH ST`). Plural suffix words (`FOUR POINTS RD`), a line with no suffix at the end and a line with no name left keep the old reading. | §232 asks for the numeral; NY corporations registry and probe review. |
| The parser does not guess: `409742ND` (4097 42ND or 40974 2ND), slash pairs (`5210/5212`), comma lists of house numbers (`multiple_addresses`) and anything no rule claims go to `unparsed`. | Observed data. |
| A house number and a unit with no street raise `missing_street_name` (`123 UNIT 1`). | Library choice. |
| Output labels only (no parse rule, no key change): in the usaddress labels (`parse_tokens`, `tag`, `doorplate parse --usaddress`) a single letter that opens the house number as a token of its own, with a digit after it, is `AddressNumberPrefix` and the rest `AddressNumber` (`E 7379 OAK HOLLOW RD`). `street_number` is `E7379`; a glued `E7379` is one `AddressNumber` token. | usaddress label compatibility; NAD field `AddNum_Pre`; library choice for the label mapping (#651). |

### Units

| Rule | Source |
|---|---|
| A unit is a designator and value (`APT 4B`), `#` and value, a designator with `#` (`UNIT # 4`), or a designator alone (`REAR`, or `UNIT` with no number where C2 requires a range). Up to two, the first in input order in `unit_*`. An ordinal before a designator is its value (`3RD FLOOR`). After a whole unit an exact copy of the city is dropped even when it starts with a suffix word; as a last resort a whole segment that repeats the city's last words is a cut-off copy (`RD,CLOUD` before `ST CLOUD`). Corpus `rg-132` to `rg-134`. | Florida address data. |
| A municipality-type prefix before the city (`VILLAGE OF PINECREST`, `TWP OF`) is read off for the place when the city as written is not one; `place` is the rest and the city stays as written. A place whose own name starts with the prefix (`CITY OF INDUSTRY`) is the place as written. No key changes. Corpus `pl-014` to `pl-021`. | Not USPS; `[place_prefix]` in `special.toml`. |
| A city that is not a place of the state but is the name of one of its counties (`HENNEPIN`, with or without `COUNTY`) gets `city_is_county`; `place` stays empty. | Not USPS; Census Gazetteer county names (`docs/places.md`). |
| A city that is a whole `[city_placeholder]` phrase (`Not stated`, `Unknown`, `N/A`) is no city: left out with `missing_city`. The street-line placeholder list is not applied to the city field. | Pub 28 has no stand-in text; data list (#468, #419). |
| A city, state or ZIP **field** that is only a null word is left out: `NaN` (a capital `Nan` is a name) in a city; `NaN`, `NULL`, `NONE`, `UNDEFINED`, `N/A` in a state or ZIP. A ZIP of only zeros and fewer than five digits is no ZIP. The word is matched on the whole field only. Corpus `nw-003` to `nw-011`. | Not USPS; MessyStreets raw tier; NAD writes `0` for a missing ZIP (#605). |
| Trailing country: `USA`, `US`, `UNITED STATES`, `UNITED STATES OF AMERICA` after a comma, ZIP or state, or as a whole field other than the street line, is cut with `country_ignored` (`[country]` in `special.toml`). `US` in a highway name is kept. Other countries are not recognized. Corpus `co-001` to `co-015`. | Pub 28 addresses are domestic and have no country line; real data. |
| On pre-split fields, line 1 that ends with the state field's two letters and a five-digit ZIP, after a house number and a name, holds the last line: street, city, state and ZIP are read from it and the fields give way when they differ (`214 N PARK AVE OAKLAND NE 68045`). Off when the state field is absent or differs, or when line 2 is given. Corpus `ll-001` to `ll-004`. | §2 (the last line is city, state, ZIP+4); Netsyms county sources fill the fields with one value for a whole county (#614). |
| `default_state`: with no state and no known ZIP, a city is looked up in the hinted state and that state's data readings (`SR`) apply. It never fills `state`. | Library behavior. |
| One line, with no ZIP: a USPS state code or name ending the street is the state (`8517 CEDAR BARK CIR AL`). Never NE or FL. CT, KY, LA, MT, PR, WY and FM only right after a suffix written shorter than the word (`CIR KY`). | Appendix B; library choice. |

### One-line input

| Rule | Source |
|---|---|
| With no commas, a state code that is also a suffix (CT, LA, WY, KY, MT, PR) is the state when the ZIP belongs to that state and a place of that state stands right before it (`9 ELM WALLINGFORD CT 06492`); otherwise the suffix (`12 SIMON CT 32505`). `WASHINGTON DC` before a ZIP is the city and DC. Corpus `nat-017` to `nat-023`. | The ZIP-to-state and place data in `crates/doorplate/data/places/`; library choice. |
| A highway route ends the street, then an optional postdirectional, a suffix after a name word (`HWY 66 FRONTAGE RD`) and a unit; the city follows (`395 COUNTY ROAD 8 LAUREL MS`). A directional with nothing after it is the postdirectional. | §237; geocode benchmark. |
| A street and city in the first comma segment are split after the street (`626 E KILBOURN AVE MILWAUKEE, WI`), unless the segment ends in a suffix or directional (`427 SOUTH LA SALLE STREET, 60605` is all street). | usaddress test data. |
| A unit starting the city's segment belongs to the street (`..., # 234 SANTA FE NM`). | Bug fix (usaddress test data). |
| Area words (`DOWNTOWN`, `UPTOWN`, `OLD`, `OLDE`, `CENTRAL`) right after the suffix and before a city the place list knows are part of the city (`123 MAIN ST DOWNTOWN MIAMI FL 33101`). `NORTH MIAMI` is unchanged. `[area]` in `special.toml`. Corpus `rg-202`, `rg-205`, `rg-206`. | Not USPS; geocode benchmark train split. |
| A spelled-out compass word right after the suffix with words after it opens the city when no known place follows (`123 MAIN ST NORTH QUINCEBROOK FL 33101`); before a known city it is the postdirectional, a comma ends the street, an abbreviation stays the postdirectional. Corpus `rg-203` to `rg-205`, `rg-224` to `rg-227`. | §233 does not say how to tell a city's first word; geocode benchmark and Florida DBPR records (`tools/compare/oneline_fl.py`). |
| A word that opens a city name and is also a suffix (`LAKE`, `PARK`, `FOREST`, `FORT`, `PORT`, `MOUNT`, `HARBOR`, `VALLEY`) after the street's own suffix, with another word after it, starts the city (`123 MAIN ST LAKE QUINCEBROOK`). Not when a later suffix ends the street, nor inside the name (`OAK PARK RD`); a place the list knows wins. `[city_head]` in `special.toml`. Corpus `rg-212` to `rg-217`. | Not USPS; chosen by net gain on the geocode benchmark train split. |

### Second line

| Rule | Source |
|---|---|
| A line 2 or segment that is exactly the city field is a copy and is skipped, even when its first word is a suffix (`CAPE CORAL`). A line 2 that repeats the end of line 1 (`9453 LUTOO LANE` / `LUTOO LANE`) is skipped with `second_line_skipped`. | Florida address data. |
| Line 2 text used or dropped with no component of its own is reported, with no change to any component: `second_line_skipped` (a copy or a no-data line), `second_line_in_street` (line 2 joins the street: `COUNTY RD` / `A`), `second_line_building`. A lone directional on line 2 after a line 1 that ends in a suffix is the unit; otherwise the postdirectional. Corpus `ld-001` to `ld-008`. | Not USPS; Netsyms review. |
| A street cut across lines: line 1's street has no suffix and the next line or segment is a suffix, with at most a number before it and a directional after (`8725 NW` / `18 TER`, `6556 CHESTNUT` / `CIR`). A line 2 of name words stays unparsed. | Florida address data. |
| Words only on line 2 under a PO Box line with no street are the attention line: `PO BOX 1234` / `JANE ROE`. One to four tokens with no digit, suffix, designator, directional, highway, box word or placeholder. A suffix word (`ELDER RD`) stays unparsed. Corpus `nm-001` to `nm-006`. | §214; probe review (31 of 50 corrections). |
| Words only on line 2 under a street are the attention line when they look like a firm or a person: `JANE ROE`, `HARBOR & PINE PC`. Two to four plain words, or up to seven with `&` or a business word; not a digit, suffix, designator, government, lot or level word, a single word, a known place or a repeat. Field form only. | §213 puts a recipient above the delivery line; VA review and a 50-card review. |
| A fraction (`1/2`, `3/4`) alone in line 2, or opening a longer line 2, is the house number's fraction: `123 MAIN ST` / `1/2` is `123 1/2 MAIN ST`. Only when line 1 starts with a number with no fraction; a PO Box and a letter before the fraction are left. Pre-split input only. | §232 (the fraction); national address database (42,598 rows). |

### Left as it is on purpose

Standing decisions, not reopened without new evidence: the data does not say which reading is right, or a rule costs more than it gains.

| Input and what the parser does | Source |
|---|---|
| A trailing number in the street (`SHORE ROAD 20`) is a unit. Left as it is: ambiguous and state-specific. | Standing decision; waits for the state-pattern pass. |
| `NORTH POINT DR` and `WEST END AVE`: `NORTH` is the predirectional. Left as it is: kept for the key. | Standing decision; NAD labels it the same way in about 0.07% of rows. |
| A unit inside the number field (`1120 -202`, `1535 227`): the second number stays unparsed. Left as it is: source stuffing and true ranges look alike. | Standing decision; class D of the Netsyms review. |
| `missing_street_number` shapes in a split source (decimals, `MILEPOST 4.2`, `BLOCK 100`, `HWY 12` in the number column, a slash range that repeats the number, Puerto Rico lot codes `K7`) stay unparsed with the warning. Left as it is: distinct shapes or source errors. | Standing decision; decisions in the issue tracker. |
| `CMR 1234 BOX 56, APO AE 09012` is read as a street, not as `military`. Left as it is: `CMR` is not in current §238.1 and the only evidence is the benchmark suite's own templates; recognizing it would turn a street key into a military key. | Standing decision; `docs/key-format.md`, "Changing the key". |
| Business and building names on line 2 or 3, or in the address position of line 1, are dropped with `unparsed_remainder`. Left as it is: not in the key. | Standing decision; Florida DBPR files (class E). |
| An abbreviated directional after the suffix before a city (`MAIN ST N BIRMINGHAM`) is the postdirectional. Left as it is: reading it as the city's first word broke 10 to 17 times as many cities as it fixed. | Standing decision; geocode benchmark and Florida one-line accuracy. |
| A lone directional letter as the whole of line 2 (`E`) is the street's postdirectional. Left as it is: ambiguous with a street continued across lines. | Standing decision; NAD labels it a unit in about 0.05% of rows. |

## Emitter rules

### USPS emitter (`emit/usps.rs`, `ParsedAddress::to_usps`)

Output: `UspsAddress { line1, line2, city, state, zip }`, plus `last_line()` (`CITY ST ZIP`) and `lines()` (mailpiece order). The layout rules were checked against the live pages named under "Lexicon tables", the examples in 238 and 239 being images (`images/28c2_019_1.jpg`, `28c2_019_2.jpg`, `28c2_020_1.jpg`).

| Rule | Source |
|---|---|
| Uppercase. | §212 (uppercase preferred); A1. |
| Punctuation dropped (`. , ' " ; : ( )`), apostrophes included (`O'BRIEN` is `OBRIEN`). Kept: the hyphen in ZIP+4, house numbers and names (`112-10 BRONX RD`, `MID-ISLAND`), the slash in fractions (`123 1/2 MAIN ST`) and a period between digits (`39.2 RD`). `&` and `@` are left as given. Corpus `p28-punct-001`. | §222 (punctuation may be omitted, except the ZIP+4 hyphen); A1; §232 (periods, slashes, hyphens; a hyphen in a name may become a space, which we do not do); §354 (removal list, with `&` and `@` as an optional step); D1, D4. |
| Street line order: number, predirectional, name, suffix abbreviation, postdirectional, unit, one space between; directionals abbreviated. | §231; §233.1, 234 (as in the street-line rows). |
| The unit goes at the end of the delivery line (`APT 4`). An unknown designator is written `# 4` with a space; a known one drops the `#` (`APT #4` is `APT 4`). A designator with no number stands alone (`REAR`). Two units are written in input order. | §213 (preferred location; no `#` when the designator is known); 213.2 (space after `#`); Appendix C2. |
| No fixed line length. `to_usps()` keeps the unit on `line1`; `to_usps_wrapped(max_line)` moves the unit to `line2` when `line1` is longer than `max_line`. On a mailpiece `line2` goes immediately above `line1`, which is the order `lines()` returns. | §35 (the label sets the length); §213.3, 343.1, 356 (a unit that does not fit goes on the line above). |
| Last line: `CITY ST ZIP`, one space between, no comma, ZIP+4 with a hyphen. Pub 28 prefers two spaces before the ZIP and allows one; we use one, as its examples do. | §224; §222; examples in 238, 239 and 341. |
| City names are written as parsed. No SAINT/ST, FORT/FT or MOUNT/MT rule is applied: Pub 28 says to spell city names in full and allows only the City State file's 13-character forms, which this library does not have. | §221, 223. |
| Military: a post office (APO, FPO, DPO) takes the city's place (`APO AE 09001`); the delivery line is `<type> <number> BOX <box>` with box zeros kept (`UNIT 9900 BOX 0500`). The corpus matches the examples in 238.1 and 239. | §225.1, 238.1, 239 and their examples. |
| General delivery: `GENERAL DELIVERY`, spelled out. | §261. |
| Route numbers are written as given, so `RR 02` keeps its zero; the key drops zeros from route numbers (`RR 02` and `RR 2` share a key; `COUNTY ROAD 023` is `COUNTY ROAD 23`; all-zero keeps one) but keeps them in box numbers (`PO BOX 0123`). Box hyphens are kept as given. Corpus `rg-182` to `rg-188`. | §242, 243, 252, 252.1, 282 (a leading zero "is not necessary"); the route number is a function of the parse in the key only. |
| A state name inside a highway name is written as its code (`KENTUCKY STATE HIGHWAY 625` is `KY STATE HIGHWAY 625`; `KENTUCKY 440` is `KY HIGHWAY 440`); a state that is the whole name stays spelled out (`OKLAHOMA AVE`). Corpus `p28-highway-028` to `037`. | Appendix F and its note; §358. |
| Dual address: the PO Box alone, without the street's units; the key and the RESO output use the street. | §215 and its example (`28c2_005.htm`): eliminate dual addresses if possible; the delivery address is normally the PO Box. |
| The attention line is not emitted. | §214 (above the recipient, outside the lines this library writes). |
| Parts the parse did not find are left out; `diagnostics` is not consulted and unparsed text is not emitted. | Library behavior. |
| Key punctuation rule 1 of `docs/key-format.md` cites §222 and 354. | §222, 354. |
| Every Appendix F "Examples in Use" entry gives its standard form, except `SR MM` (left to state data). | Appendix F; `tools/pub28/verify.py`. |
| Highway contract route: `HC <route> BOX <box>` (`HC 68 BOX 23A`). HIGHWAY CONTRACT, ROUTE, NUMBER, NO, STAR ROUTE and `#` are dropped, so `STAR ROUTE 68 BOX 23A` and `HC RTE #68 BOX 23A` both become it. Route and box may hold letters. | §251. |
| Rural route: `RR <route> BOX <box>`. RURAL, NUMBER, NO and `#` are dropped; RFD and RD become RR; a leading zero is not needed; hyphens in the box are kept as given; no street or town name on the line. | §241 to 245 (244 for RFD and RD; 245 for no street name). |
| PO Box: `PO BOX <number>`. CALLER, FIRM CALLER, BIN, LOCKBOX and DRAWER become PO BOX; the value may be a letter; box zeros are kept. A post office street address with `# <box>` or `UNIT <box>` is a street address with a unit, not a PO Box line. | §281 to 283; §282 (zeros); §284. |
| Highways: `[<state code>] <standard prefix> <route>` (`CR 1185` is `COUNTY ROAD 1185`, `HWY FM 1320` is `FM 1320`, `I10` is `INTERSTATE 10`, `US 41 SW` is `US HIGHWAY 41 SW`). Routes may hold letters (`COUNTY HIGHWAY 60E`). After the route only the last word is abbreviated, as a suffix: `HIGHWAY 3 BYP ROAD` is `HIGHWAY 3 BYPASS RD`, `HWY 66 FRONTAGE ROAD` is `HIGHWAY 66 FRONTAGE RD`. | §237; Appendix F. |
| `UNITED STATES HIGHWAY 27`, `UNITED STATES HWY` and `U S HIGHWAY` read as `US HIGHWAY`, so the spellings key alike. After a leading word (`OLD UNITED STATES HIGHWAY 27`) or before a route pair `n-m` or `n/m` the name keeps the word and the pair and reads only the prefix, with no `possibly_truncated`. A route number must follow (`UNITED STATES POSTAL SERVICE` is not a road). | NAD writes the prefix spelled out (#543, #608); Appendix F. |

### Display emitter (`emit/display.rs`, `ParsedAddress::to_display`, `to_long`)

Output: `DisplayAddress { line1, city, state, zip }`, plus `last_line()` and `lines()`. **Neither form is a Pub 28 form**: they show an address to a person, so the source of each rule is the project's own style. Use `to_usps()` for mail. The words come from the same tables as the USPS emitter, so the two never disagree on what a word is.

| Rule | Source |
|---|---|
| `to_display()`: Pub 28 abbreviations in mixed case (`123 N Main St Apt 4`); directionals stay upper case. `to_long()`: directionals, suffixes and designators spelled out (`123 North Main Street Apartment 4`). The state stays a two-letter code and the ZIP as is. | Project style; words from `data/directionals.toml` and Appendix C1 and C2. |
| Capitalized words; hyphen- and slash-separated parts cased alone (`Mid-Island`); a word with a digit is upper case except an ordinal's suffix (`5th`, `23B`); a leading `Mc` is kept; `of`, `the`, `de`, `la`, `del`, `and` are lower case unless first. | Project style; judged on the geocode benchmark's addresses. |
| Apostrophes were dropped by the parse (`OBRIEN`), so `Obrien` is the best case. | §354. |
| Unknown unit designator `#4` (no space; `# 4` is a mailpiece form); `PO Box 12`; `RR 2 Box 152` (long: `Rural Route`, `Highway Contract Route`); `PSC 1650 Box 10`, `Unit 9900 Box 0500`; `General Delivery`. A dual address is the PO Box alone. | Project style; the line structure follows the USPS emitter. |
| Highway names: the state code and one- or two-letter prefixes upper case, the rest capitalized (`KY State Highway 625`, `US Highway 41`, `FM 1200`, `County Road 23E`). | Project style over Appendix F. |
| The city is title-cased as parsed (`St Petersburg`); `APO`, `FPO`, `DPO` stay upper case. | Project style. |
